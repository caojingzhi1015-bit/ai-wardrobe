# AI 衣橱管家 · Web 版

把 `wardrobe/AGENT-PROMPT.md`（v3）的六个模块做成了一个**本地优先**的单页应用。
数据只存在这台电脑的浏览器 IndexedDB 里，`library.json` 是唯一数据源，随时可以导出/导入。

## 启动

必须走 http 打开（IndexedDB 在 file:// 下不可用）：

```
cd app
python -m http.server 8777
# 浏览器打开 http://127.0.0.1:8777
```

## 模块对照

| 界面 | 对应 prompt 模块 | 说明 |
| --- | --- | --- |
| 衣橱 | — | 单品数据库浏览/编辑/筛选，商品图墙底色 #F5F3F0（略暖灰白） |
| 批量入库 | 模块一 | 拖图 → 解析 `{价格}-{平台}-{品牌}-{简述}` 文件名 → 填元数据 → 写入库；支持裁剪拆多件、AI 补全（可选） |
| 风格画像 | 模块二 | 冷启动值 + 手动编辑；可上传 ≥5 张真实穿搭照让视觉模型整体覆盖 |
| 购买评估 | 模块三 + 四 | 按写死公式打分（色彩40/廓形20/材质15/场合15/价位10），闲置概率按搭配件数分档，生成 ≥3 套方案，可下载 .md 报告 |
| 搭配工作台 | 模块五 | flat lay 程序化拼贴：1080×1920、纯白、左右120/上下160、件间距50、品类宽度系数、溢出整体等比缩放 |
| 数据与设置 | 模块六 | 模型 API（OpenAI 兼容）、JSON 导入导出、zip 全量导出；衣橱页支持「导入 zip」（与导出同结构，合并式不清空，`style-profile.json` 不覆盖现有画像） |

## 商品图形态（当前实际方案）

- **应用内主力是裁剪版 JPG（非透明 PNG）**：`wardrobe/scripts/crop_ui.py` 用抠图掩膜定位衣服主体边界框、紧裁原图（零像素重绘），截掉截图里的状态栏 / 价格条 / 悬浮按钮 /「查看同款」等 UI 文字，保留衣服形态；背景杂乱的只去商品信息。
- 同时保留同名不透明 PNG 兼容副本（供旧浏览器缓存过渡），但**不再使用透明抠图 PNG 进应用**。透明抠图成品仍备份在 `wardrobe/tmp/matte-out/final/`，可随时恢复。
- 硬约束不变：**禁止** GPT-Image / Seedream / SD 等生成式模型重绘商品；颜色保真、细节全保留。
- 商品图墙底色 `#F5F3F0`（略暖灰白），flat lay 画布是纯白 `#FFFFFF`，两回事。

## 与 AGENT-PROMPT 的差异（诚实声明）

1. prompt 的主入口是 `wardrobe/inbox/` 文件夹扫描；网页版改成**拖拽上传**（浏览器拿不到任意本地目录权限，拖进来等价）。原 inbox 命名约定完全兼容。
2. 图片存在 IndexedDB 而不是 `items/` 目录；「导出全部（zip）」会按 `items/{slug}.jpg`、`thumbs/{slug}.jpg`、`outfits/{id}.png` 的目录结构打包，可直接落回 `wardrobe/`。
3. 多件拆分不是自动分割，而是手动框选裁剪（1:1 像素，不缩放），更可控也更诚实。
4. 评估报告默认用规则文案；配置文本模型（DeepSeek 等）后可让模型把结论写成人话，但分数和概率仍是公式算的。

## 技术栈

零构建、零依赖：原生 HTML/CSS/JS + IndexedDB；图片处理全在浏览器 Canvas；模型调用走 OpenAI 兼容 `/chat/completions`。`tools/smoke-v2.js` 是基于 playwright-core 的冒烟测试（启动服务后运行，26 项）。
